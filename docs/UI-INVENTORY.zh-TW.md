# 介面功能清單（重做介面用）

依 1.2.1 的程式碼整理：桌面版（tkinter）、Android（Compose）、iPhone（SwiftUI）三個平台各自的畫面、按鈕、選單、對話框與快捷鍵，最後是三平台差異與「新介面必須保留的行為」。

文字一律照抄程式裡的字串（中文 / English）：桌面版來自 [i18n.py](../src/aio_receiver/i18n.py)，Android 來自 [values-zh-rTW/strings.xml](../android/app/src/main/res/values-zh-rTW/strings.xml)，iOS 來自 [Localizable.xcstrings](../ios/MyApp/Localizable.xcstrings)（中文用詞與 Android 相同）。

**總覽**

| | 桌面版 | Android | iPhone |
|---|---|---|---|
| 畫面結構 | 單一視窗，由上到下分區 | 底部 4 個分頁 | 底部 4 個分頁 |
| 選單列 / 右鍵選單 | 無 | 無 | 無 |
| 快捷鍵 | 4 個（主視窗）＋2 個（設定對話框） | 無 | 無 |
| 手勢 | 無 | 軌跡：拖曳平移、雙指縮放 | 軌跡地圖：拖曳、縮放（MapKit） |

### 4. 主體三欄

**導航 0x04** — `NavPanel` [panels.py:329](../src/aio_receiver/ui/panels.py:329)

- 標題右側串流燈：● ＋「100 Hz 12 ms」或「中斷 3.2 秒」或「沒有資料」
- 三顆對準燈：粗對準 / 初始航向 / 精對準（亮為綠）
- 輔助更新（距上次出現）：每個 aiding 旗標顯示「名稱 0.4s」，1.5 秒內出現過為綠底
- 12 個數值：緯度、經度、高度、航向、水平速率、垂直速度、滾轉/俯仰、位置 σ、速度 σ、姿態 σ、GPS 週秒、資料延遲（超過上限為紅）；資料過時整欄變灰

**狀態 0x05** — `StatusPanel` [panels.py:392](../src/aio_receiver/ui/panels.py:392)

- 串流燈：「2.0 Hz 0.3 秒前」
- 6 個數值：狀態（就緒綠、故障/降級紅）、GNSS 品質、工作階段、序號、導航頻率、0x04 延遲
- 不可用原因：逐行紅字；沒有時顯示綠色「無」
- 成立條件：18 項，● 成立 / ○ 不成立，分兩欄
- 0x05 過時：所有值變灰，絕不顯示綠

## 五、新介面必須保留的行為（功能面，不是外觀）

這些在現有介面裡，換外觀時容易被漏掉：

1. **每 100 ms 重畫一次**，而且無論這一格出了什麼錯，下一格都照排 — [main_window.py:80](../src/aio_receiver/ui/main_window.py:80)
2. **畫面資料超過 0.5 秒沒更新 → 紅色不可用**「監看程式沒有回應」 — [main_window.py:96](../src/aio_receiver/ui/main_window.py:96)
3. **畫面更新發生例外 → 紅色不可用**「畫面更新錯誤：…」，絕不留下舊畫面
4. **可用 → 不可用的瞬間**：色帶閃三次，勾選「中斷時提示音」時響鈴 — [panels.py:147](../src/aio_receiver/ui/panels.py:147)
5. **判斷寫在視窗標題**，工作列看得到
6. **過時的值顯示為灰色**，不能保留綠色
7. **換語言時重建畫面但不中斷接收**；只有接收／判斷規則的設定改變才重新監聽
8. **顏色只用來表達意義**（綠＝可用、黃＝預期中的等待、紅＝出問題、灰＝沒資料/已停止），不做裝飾
9. 重播時要有明顯的「不是即時資料」標示，且不能開始記錄
10. 收到第一個封包前，要告訴使用者這台電腦的 IP 與要怎麼設定 Jetson
